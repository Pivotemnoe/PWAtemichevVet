# Email/MAX: сообщения и возвраты

Первая версия 20261008-retention-1. Одна первая отправка на аккаунт. Недельная серия выключена; тексты для неё подготовлены отдельно. Действующие вопросы после оценки состояния и даты — отдельные события.

## Работа

- `RETENTION_ENABLED=1` включает отправку. По умолчанию 0.
- `RETENTION_WEEKLY_SERIES=0` сохраняет режим одной первой отправки. Даже при выборе пользователем недельных предложений серия не начинается сама.
- Основной канал — первый подтверждённый доступный email/MAX, затем пользователь может изменить его. На оба канала одновременно не отправляем.
- Первое сообщение — помощь с кабинетом по функции, для которой он создан. Недельные предложения по умолчанию выключены и выбираются отдельно.
- Общие сообщения: одно за 7 дней, 10:00–20:00 в выбранном часовом поясе. Новый аккаунт получает первое общее сообщение не раньше чем через сутки.
- Актуальный follow-up или выбранная дата получают приоритет. Клинические задачи старше 48 часов не отправляются как нынешний вопрос о самочувствии; исходные записи не удаляются.
- `scripts/send_pwa_followups.sh` вызывается существующим systemd-таймером. После push обрабатывает до трёх email/MAX заданий за запуск.
- Подтверждённый переход и действие отменяют ненужное сообщение. Остановку MAX-бота, отключение сообщений и объединение аккаунтов учитываем.

## Учёт

Схема добавляется после основной `db.init_db`: preferences, channel availability, outbox, activity, events. Новые таблицы имеют внешние ключи владельца; объединение аккаунтов переносит их и отменяет повторное первое сообщение.

Статусы очереди: queued, sending, accepted, failed, unknown, cancelled, skipped. Atomic claim защищает от параллельной отправки. Незавершённая попытка и неоднозначный сетевой результат переходят в unknown, без автоматической повторной отправки. Явный MAX 429 повторяется ограниченно. HTTP 403/404 отключает недоступный канал.

`accepted` означает SMTP/API receipt, не прочтение. GET ссылки не создаёт событие возвращения и не отключает сообщения. Переход учитывается клиентским POST после входа в свой аккаунт. Signed link не авторизует доступ к медицинским записям. Отключение работает отдельным POST, включая стандартный email one-click unsubscribe.

Полезные действия и оплата связаны с последним подтверждённым переходом не дольше 7 дней после отправки. Оплата берётся только из подтверждённого платежа после перехода. Такая связь не является доказательством причинного эффекта сообщения.

Админка `/admin#retention`: регистрация/вход/первая запись/оплата для одной когорты аккаунтов за 7 и 30 дней; очередь; принятые каналом сообщения; переходы; записи; ответы; Plus; ошибки; отписки; разрезы по каналу и сценарию; D1/D7/D30 по новым сеансам; отдельные шаги PWA/push.

Новые сеансы считаются с интервалом неактивности 30 минут, без повторного ввода кода. D1/D7/D30 включают только аккаунты с измеренным первым сеансом и полностью прошедшими соответствующими сутками. Исторические пропуски не восстанавливаются предположениями.

PWA: показ предложения после полезной записи на телефоне; отдельная инструкция установки; выбор установки Chrome; запуск standalone; подключение push. Статус push определяется по подписке текущего устройства, а не по общей подписке аккаунта.

## Эндпоинты

- `GET/POST /api/retention/preferences` — только свой аккаунт.
- `POST /api/retention/activity` — видимая страница своего аккаунта; установка/инструкция и signed message attribution.
- `GET /api/admin/retention` — авторизация администратора.
- `POST /api/internal/retention/send?dry_run=true` — monitoring secret; создаёт/проверяет очередь, не обращается к внешним каналам.
- `POST /api/internal/retention/send?limit=3` — monitoring secret; отправка при включённом флаге.
- `GET /r/{signed-token}` — переход в кабинет; `GET/POST /r/{signed-token}/stop` — форма/отключение.

## Проверки

`make check` включает API, новую очередь, мониторинг, атрибуцию, публичное сохранение, JS и manifest. Новые проверки покрывают параллельные воркеры, повторные отправки, неоднозначную доставку, запрет чужого аккаунта, GET-сканеры, отключение, оплату, сроки follow-up, объединение аккаунтов, недельный режим и состав email.

Локальный вымышленный предпросмотр — `scripts/qa_retention_preview.py`. Он отключает провайдеры и использует отдельную `/tmp` базу. Не включать этот QA-скрипт в боевой пакет: его локальная вспомогательная авторизация предназначена только для проверки интерфейса.

MAX stop events согласованы с официальной документацией: https://dev.max.ru/docs-api/objects/Update .
