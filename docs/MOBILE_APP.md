# TemichevVet Android, iPhone и PWA

Актуальное обновление 0.1.2 и подготовка отдельного iOS-приложения описаны в
`docs/MOBILE_QA_20261021.md`. APK 0.1.2 опубликован на
[странице установки](https://temichevvet.ru/android). TestFlight пока не настроен.

Для iOS используется `npm run ios:sync`. Нативные файлы находятся в `ios/`,
входная точка — `mobile/ios-entry.js`, календарный планировщик —
`mobile/ios-reminders.js`. Облачный процесс GitHub Actions `ios.yml`
компилирует производственную версию без подписи, затем тестовую версию для
симулятора с изолированным сервером `mobile/qa_server.py`. Xcode на Mac
владельца не устанавливается. Облачные артефакты с пометкой `UNSIGNED` и
`Simulator` не являются файлами для установки на настоящий iPhone.

На iOS Debug использует другой bundle ID и схему `temichevvet-qa://`.
Release проверяет боевой HTTPS API, отсутствие debug-параметров, версию и
отсутствие приватных файлов. iOS-ресурсы нельзя использовать при сборке Android:
платформа записана в `mobile-build.json` и проверяется обеими сборками.

## Следующий этап для TestFlight

1. Проверить участие владельца в [Apple Developer Program](https://developer.apple.com/account/).
   Для нового участия нужны Apple Account с двухфакторной защитой, подтверждение
   данных, соглашение и оплата. Базовая стоимость — 99 USD в год, местная цена
   зависит от региона: [официальная регистрация](https://developer.apple.com/programs/enroll/).
   У физлица продавцом отображается его настоящее имя; у организации — название
   юридического лица, для проверки которого Apple обычно требует D-U-N-S.
2. Создать запись TemichevVet в App Store Connect с идентификатором
   `ru.temichevvet.app` и получить идентификатор команды Apple. Не менять
   идентификатор уже созданной записи без проверки существующих приложений.
3. Настроить подпись на облачном сборщике: сертификат распространения и профиль
   хранятся в защищённых секретах, не в Git, веб-ресурсах или переписке.
   Текущий `ios.yml` проверяет сборку без подписи; подписанный архив и загрузка
   в TestFlight добавляются после доступа к команде Apple.
4. Установить подписанную сборку через TestFlight на настоящий iPhone и проверить
   камеру, разрешения, уведомления, оплату и сохранение данных при обновлении.
5. Перед App Store оформить сведения о данных и выбрать допустимую для выбранного
   магазина/региона оплату цифрового Plus по
   [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/).
   Текущая внешняя ЮKassa сама по себе не подтверждает выполнение этих правил.

Установка Xcode на Mac владельца для этой схемы не нужна: компиляция и подпись
выполняются в облаке. Само членство Apple не создаёт сборку и не публикует приложение.

Рабочая ветка: `codex/android-pwa-app-20261013`. Текущий Android:
[APK 0.1.2](https://temichevvet.ru/downloads/TemichevVet-0.1.2.apk).
[PWA для iPhone](https://temichevvet.ru/mobile) устанавливается через Safari.
Предыдущая версия 0.1.1 опубликована 13 октября 2026 года и сохранена;
история её выкладки: `docs/MOBILE_DEPLOYMENT_20261013.md`.

## Устройство приложения

- `web/mobile-shell.js`, `web/mobile.css`: собственные шапка, нижние вкладки, стартовый и главный экран. Включаются в APK, установленной PWA и на `/mobile`; публичная главная сайта сохраняет свой сценарий.
- `web/platform.js`: общий транспорт, предупреждение перед оплатой, внешний переход.
- `mobile/native-entry.js`: Android API через CapacitorHttp, cookie-сессия, жизненный цикл, браузер, уведомления о датах, буфер обмена и экспорт данных.
- `mobile/build.mjs`: включает веб-ресурсы в APK; секреты, базы и серверный код не копируются. Адрес API по умолчанию `https://temichevvet.ru`.
- `android/`: проект Capacitor 8.5.3, Android SDK 36, min SDK 24, Java 21. Пакет выпуска `ru.temichevvet.app`, тестовый `ru.temichevvet.app.qa`.
- `android/.../NativeDocumentsPlugin.java`: системная печать / сохранение сводки в PDF.
- Native checkout отмечается заголовком `X-TemichevVet-Client: android` или `ios`. Сервер задаёт фиксированный возврат `/mobile/payment-return`. Страница предлагает `temichevvet://payment-return`; доступ выдаётся только по серверной проверке платежа.
- `/android`: страница скачивания Android и установки PWA. `/downloads/TemichevVet-0.1.2.apk` и сохранённый маршрут 0.1.1 отдают конкретные подписанные файлы из `releases/android/`. При отсутствии файла возвращается 404.

## Локальное тестирование

`mobile/qa_server.py` использует только `.mobile-tools/qa.db`, отключает SMTP, MAX, Telegram sync, OpenAI и реальные платежи. Платёжный провайдер и успешный ответ разбора подменены локальными фикстурами. Локальные тестовые аккаунты не являются боевыми. `QA_FORCE_FAIL` в тексте обращения проверяет отказ без списания квоты.

```sh
.venv/bin/python mobile/qa_server.py
TVV_API_BASE=http://127.0.0.1:8096 TVV_DEBUG_API=1 npm run mobile:sync
adb -s DEVICE_SERIAL reverse tcp:8096 tcp:8096
```

HTTP допускается только в debug-манифесте для `127.0.0.1` / `10.0.2.2`. Release запрещает открытый HTTP и резервное копирование данных приложения. Перед сборкой выпуска обязательно повторить `npm run mobile:sync` без тестовых переменных.

При недоступности официального Google Maven на этом Mac используется локальный, некоммитящийся `.mobile-tools/maven-mirror.init.gradle`. Обычная конфигурация проекта содержит официальные репозитории. Gradle 8.14.3 скачан с официального GitHub; SHA256 проверен по https://gradle.org/release-checksums/.

```sh
make check
.venv/bin/python scripts/test_mobile_api.py
npm run mobile:test
```

## Границы проверки

- Android напоминания работают локально через `ReminderReceiver` и AlarmManager. После доставки следующий календарный повтор ставится автоматически. Поддерживаются сутки, неделя, месяц, 3/6 месяцев, год; конец месяца и високосные даты остаются привязаны к исходной дате. Расписание восстанавливается при загрузке, обновлении приложения и смене часового пояса. Android может отложить доставку при экономии энергии: точный будильник и специальное разрешение не используются. Даты, изменённые на другом устройстве, синхронизируются при следующем открытии APK. Облачный Android push ещё не настроен.
- Свойства календаря проверены JUnit, доставка закрытому приложению и переход из уведомления проверены на Tecno. Физическая перезагрузка телефона и длительный Doze отдельно не проверялись.
- Печатная сводка сохранена в реальный двухстраничный PDF через Android PrintManager; проверены текст и обе отрисованные страницы.
- Реальная ЮKassa, Telegram/MAX и iPhone проверяются отдельно от локальных фикстур. Установку PWA на реальном iPhone и обновление существующей установки принимает пользователь.
- Safari 26.6.2 проверен на Mac, включая размеры 390×844 и 320×844. Xcode/simctl на Mac отсутствуют; настоящая iOS и экранная клавиатура iPhone этим тестом не подтверждаются.
- Сервер, PWA и подписанный APK опубликованы по прямому разрешению пользователя. Отправка AAB в магазины остаётся отдельным этапом; правила оплаты выбранного магазина и реальный платёж проверяются отдельно.

## Подписанный выпуск

```sh
.venv/bin/python mobile/release.py --gradle "$PWD/.mobile-tools/gradle-8.14.3/bin/gradle" --maven-init .mobile-tools/maven-mirror.init.gradle
```

При первом создании ключа использован `--init-key`. Повторно ключ не создаётся. Материал подписи хранится отдельно: `~/.local/share/temichevvet/android-signing/`, папка 0700, файлы 0600. В APK, пакет сервера и Git он не входит. Эту папку нужно сохранить в отдельной резервной копии для дальнейших обновлений APK. Пароль не печатается в логах и исходниках.

Release проверяет `mobile-build.json`: боевой HTTPS origin и отключённый debug. Сборка выпуска с QA-адресом была намеренно проверена и отклонена. APK проверяется apksigner; AAB — jarsigner. Самоподписанный сертификат Android ожидаем, его SHA256 записан в `apk-signature.txt`.

Результат проверки версии 0.1.1: `docs/MOBILE_QA_REPORT_20261013_REVISION.md`. Предыдущие общие проверки 0.1.0: `docs/MOBILE_QA_REPORT_20261013.md`. Пакет выдачи: `output/mobile/0.1.1/`.

Логи и скриншоты проверки: `.mobile-tools/`, `output/playwright/`. Эти каталоги не включаются в сборку и Git.


## Фото и работа без связи (0.1.1)

`web/pet-avatar.js` даёт портрет или значок выбранного вида. `app/pet_photos.py` проверяет и нормализует JPEG/PNG/WebP. Фото передаётся JSON-запросом, совместимым с CapacitorHttp, и сохраняется в nullable-колонку `pets.photo_data_url`; отдельного публичного storage нет. Входное фото в галерее остаётся без изменений.

`web/offline-store.js` хранит кабинет и очередь в IndexedDB. Общий API сохраняет напоминания, отключения дат, вес, заметки и фото существующих питомцев на устройстве до отправки. POST веса/наблюдения/даты несёт `client_request_id`; SQLite-транзакции и уникальные индексы предотвращают повторное создание. Сервер проверяет сессию, владение и тариф, а не доверяет локальным данным. Ошибки не удаляют запись из очереди.

Для синхронизации новый `/api/me` возвращает `mobile_features.offline_sync=1`. Старые серверы не получают очередь до обновления. Подписанный 0.1.1 APK опубликован вместе с новым сервером/PWA. Перед выкладкой сохранена согласованная копия существующей базы; штатный `init_db` добавил nullable-колонки и индексы без замены базы и удаления прежних записей. В собственное серверное окружение установлен Pillow 11.3.0.

Первая авторизация и загрузка требуют сети. При последующем запуске приложение открывает загруженные данные без API. Синхронизация идёт при открытом приложении; закрытая PWA не обещает фоновой отправки. Android-уведомления локальные, iPhone PWA push требует сети. Разбор здоровья и оплата требуют интернет.

Подробная проверка новой версии: `docs/MOBILE_QA_REPORT_20261013_REVISION.md`. Предыдущие платёжные/PDF/общие проверки: `docs/MOBILE_QA_REPORT_20261013.md` (0.1.0). Предыдущий локальный пакет сохранён в `output/mobile/0.1.0/`.
